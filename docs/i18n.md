# Internationalization (i18n)

This document describes the internationalization architecture and usage in Fynn New Tab.

## 1. Overview
Fynn New Tab includes a fully custom, lightweight i18n system built with vanilla JavaScript. It supports runtime language switching without requiring a page reload.

## 2. Supported Languages
* **English** (`en`) - Default & fallback
* **Vietnamese** (`vi`)
* **Chinese** (`zh`)

## 3. Project Structure
* `newtab/JS/i18n/i18n.js`: The core i18n module containing the translation logic, persistence, and state management.
* `newtab/JS/i18n/locales/*.js`: Individual language definitions exporting nested key-value objects.

## 4. Translation Key Conventions
* **Hierarchical**: Keys are organized by feature (e.g., `wallpapers.errors.invalidFileType`).
* **Group by feature**: Group related strings together (e.g., `settings.search`, `settings.clock`).
* **Reuse**: Use `common.*` (e.g., `common.cancel`, `common.save`) across different UI features where appropriate.
* **Consistency**: The object structure must be identical across all locale files (`en.js`, `vi.js`, `zh.js`). Do not duplicate identical keys unnecessarily. Do not place user-facing strings directly in JS logic.

## 5. Static HTML Usage
To translate a standard element's text content, add the `data-i18n` attribute to your HTML element:
```html
<span data-i18n="common.save">Save</span>
```
When `initI18n()` is called (or when the language changes), `applyI18n()` automatically overwrites the `textContent` with the correct translation.

## 6. Attribute Translation Usage
To translate element attributes (like `placeholder`, `title`, `aria-label`), use `data-i18n-attr`:
```html
<input data-i18n-attr="placeholder:search.placeholder; aria-label:accessibility.search">
```
Format: `attributeName:translation.key`. Multiple attributes can be separated by a semicolon (`;`).

## 7. JavaScript Usage
In dynamic modules, import and use the translation helpers from `i18n.js`:
```js
import { t, tArray, tObject } from "./i18n/i18n.js";

// Basic string
button.textContent = t("common.save");

// Array of strings (e.g. for greetings)
const greetings = tArray("greeting.morning");

// Objects (for dynamic mapping)
const engines = tObject("search.engines");
```

## 8. Interpolation
Placeholders are formatted as `{parameterName}` within the locale strings:
```js
// In locale file: "searchWith": "Search with {engine}"
t("search.searchWith", { engine: "Google" });
```
Always use identical placeholder names across locales. If a parameter is missing, the literal `{placeholder}` will remain in the text, preventing runtime errors.

## 9. Pluralization
Pluralization is supported automatically using `Intl.PluralRules` behind the scenes. Define `one` and `other` variants in your locale:
```javascript
// Locale
count: {
  one: "{count} note",
  other: "{count} notes"
}

// Usage
t("notes.count", { count: 0 }); // "0 notes"
t("notes.count", { count: 1 }); // "1 note"
```
The fallback system intelligently handles locales that don't differentiate singular/plural (like Vietnamese and Chinese) by falling back to the generic or `other` definitions.

## 10. Dynamic Language Switching
When the language changes via `setLanguage()`, a global `fynn-language-change` event is dispatched. 

Modules should subscribe to this event to immediately re-render dynamic content:
```javascript
import { onLanguageChange } from "./i18n/i18n.js";

onLanguageChange(() => {
  renderDynamicUI();
});
```
`applyI18n()` is automatically invoked on language changes to handle static HTML elements.

## 11. Adding a New Language
To add a new language (e.g., Japanese):
1. **Create the locale module**: Create `newtab/JS/i18n/locales/ja.js`.
2. **Export the locale object**: Export `ja` following the exact structure of `en.js`.
3. **Register it**: In `newtab/JS/i18n/i18n.js`, import `ja` and add it to the `LOCALES` object.
4. **Ensure parity**: Verify all existing keys are translated and structural parity is maintained.
5. **Add to Settings**: Add an `<option value="ja" data-i18n="settings.language.ja">` to the `#languageSetting` select inside `index.html`.
6. **Test**: 
   - Verify browser detection (`detectBrowserLanguage`).
   - Test persistence (`localStorage`).
   - Test runtime switching and fallback behavior.

## 12. Translation Review Checklist
* Are all interpolation variables (`{count}`, `{engine}`, etc.) included in the translation?
* Is capitalization and punctuation consistent with the English baseline?
* Are specific product terminologies (Dashboard, Widget, Wallpaper) handled consistently?

## 13. Common Mistakes
* **Hardcoding Fallbacks**: Never hardcode English text in JS if a key fails. `t()` automatically returns the requested key name, and logs a warning to the console to help you debug.
* **Redundant Listeners**: Do not attach duplicate `onLanguageChange` listeners. Use state checks if your `init` function can run multiple times.

## 14. Testing Checklist
* Switch languages rapidly; ensure no UI flicker or duplication.
* Reload the tab to verify the language remains persistent.
* Open a second New Tab; change the language on Tab 1, and ensure Tab 2 synchronizes automatically via the `storage` event.
